# פרוטוקול הצוות — Claude, Codex, ChatGPT

שלושה סוכנים עובדים על אותו ריפו, ולפעמים באותו זמן. המסמך הזה קובע איך לא דורסים זה את זה.
**כל סוכן חייב לקרוא אותו לפני כל משימה.**

## התפקידים

| מי | תפקיד | מה הוא עושה | מה הוא **לא** עושה |
|---|---|---|---|
| **Claude** (Claude Code) | מנהל העבודה | מתכנן, כותב את רוב הקוד, סוקר את העבודה של כולם, ממזג ל-`main`, ומעדכן את `BOARD.md` | — |
| **Codex** (מחובר ל-GitHub) | מפתח | משימות קוד מוגדרות היטב מתוך `docs/team/codex/` | לא עורך את `BOARD.md`, לא ממזג, ולא נוגע בקבצים מחוץ להיקף המשימה |
| **ChatGPT** (עם מחבר GitHub) | קריאייטיב ומחקר | תמונות, טקסטים שיווקיים, תסריטים, נוסחי תקנון ומחקר שוק, לפי `docs/team/chatgpt/` | לא כותב קוד לריפו. התוצרים מגיעים דרך הבעלים או PR לתיקיית `marketing/inbox/` בלבד |
| **הבעלים** | מחליט ומשלם | פעולות ב-`docs/launch/USER-ACTIONS.md`. מעביר תוצרי ChatGPT | — |

## עשרת הכללים

1. **`BOARD.md` הוא מקור האמת, ורק Claude כותב בו.** כך אין קונפליקטים על הקובץ. סוכן אחר מדווח בקובץ משלו: `docs/team/reports/<TASK-ID>.md`. Claude קורא את הדוח ומעדכן את הלוח.
2. **משימה מתחילה רק אם היא `ready` ושייכת לך** בעמודת "מי". משימה `in-progress` של סוכן אחר: לא נוגעים.
3. **לכל משימה יש "היקף קבצים"** (בעמודת "אזור" בלוח ובקובץ המשימה). עורכים **רק** קבצים בהיקף. צריך לגעת במשהו מחוצה לו? עוצרים, וכותבים את זה בדוח.
4. **ענף לכל משימה, ואף פעם לא `main` ישירות.**
   - Claude: `claude/<...>` · Codex: `codex/<TASK-ID>-<slug>` · ChatGPT: `gpt/<TASK-ID>-<slug>` (אם בכלל)
   - **אסור** לדחוף לענף של סוכן אחר, ואסור לעשות לו force-push.
5. **לפני שמתחילים: `git fetch origin main` ויוצרים את הענף מ-`main` העדכני.** לפני פתיחת PR: rebase על `main`.
6. **PR קטן ואחד לכל משימה.** הכותרת מתחילה במזהה: `[CX-03] ...`. ב-PR מפרטים מה נעשה, מה נבדק (פקודות ותוצאות) ומה לא נעשה.
7. **בדיקות לפני PR:** `npm run lint`, `npx tsc --noEmit`, `npm run test:regressions`, ו-`npm run build` כשנוגעים בקוד של האתר. ב-`history-talk/`: `npm run typecheck && npm test`. **אסור לדלג על בדיקה, לנטרל אותה או למחוק אותה כדי לקבל ירוק.**
8. **קבצים generated לא עורכים ביד.** הרשימה המלאה ב-`CLAUDE.md`: `src/data/quizzes/*` המיובאים, `src/data/exams/*`, `photos.ts` למיניהם, `geometry.ts`, `resources.ts` ועוד. משנים את המקור ומריצים את הסקריפט.
9. **סודות לא נכנסים לריפו.** לא בקוד, לא ב-MD ולא בהודעות commit. משתמשים בשמות של GitHub Secrets או של `wrangler secret`.
10. **שפה ועיצוב:** הממשק בעברית ו-RTL. צבעים רק דרך הטוקנים (`text-txt-dim`, `bg-card`...) ולא צבעי Tailwind גולמיים. `withBasePath()` לנתיבים, ו-`useSyncExternalStore` ל-localStorage. פירוט ב-`CLAUDE.md`, "מוסכמות ועיצוב".

## מחזור החיים של משימה

```
backlog → ready (Claude כתב קובץ משימה) → in-progress (מי שלקח) → review (PR פתוח / דוח הוגש)
       → done (Claude מיזג או קיבל) | blocked (מחכה לבעלים — מצוין בלוח)
```

## איך Codex לוקח משימה

1. קורא את `docs/team/BOARD.md` ומחפש שורה עם `מי = Codex` ו-`מצב = ready`.
2. קורא את קובץ המשימה `docs/team/codex/<TASK-ID>.md`. בראשו יש פרומפט מלא.
3. עובד בענף `codex/<TASK-ID>-<slug>`, ופותח PR ל-`main` עם הכותרת `[<TASK-ID>] ...`.
4. כותב `docs/team/reports/<TASK-ID>.md`: מה נעשה, מה נבדק, שאלות ומה נשאר. הקובץ נכנס **באותו PR**.
5. לא ממזג. Claude סוקר, מבקש תיקונים בתגובה ל-PR או ממזג.

## איך ChatGPT מגיש תוצר

- **טקסט** (קופי, תקנון, תסריט): קובץ Markdown. הבעלים שומר אותו ב-`marketing/inbox/<TASK-ID>/`, או שאם יש ל-ChatGPT הרשאת כתיבה, PR לאותה תיקייה בלבד.
- **תמונות:** PNG/WebP ב-`marketing/inbox/<TASK-ID>/`, עם `README.md` קצר: מה כל קובץ, הפרומפט שיצר אותו, וגודל.
- Claude עובר על התוצרים, בוחר, מעבד (גודל, פורמט, דחיסה) ומעביר למקום הסופי באתר (`public/marketing/...`).

## כשיש ספק

כותבים שאלה בדוח המשימה (`reports/<TASK-ID>.md`) תחת `## שאלות ל-Claude`, ומפסיקים. לא מנחשים על נושאים של כסף, אימות, מחיקת תוכן או נתוני משתמשים.
