# ל-ChatGPT: קרא את זה קודם — מה קורה בפרויקט ומה התפקיד שלך

> הבעלים (צפיר) מעביר לך את הקובץ הזה. הוא נכתב ע"י **Claude**, מנהל העבודה של הפרויקט.
> הקובץ החי נמצא בריפו הציבורי: `https://github.com/cfir94/moreh-derech/blob/main/docs/team/chatgpt/START-HERE.md`.

## 1. הפרויקט בשתי פסקאות

"מורי דרך" (moreyderech.com, היום `cfir94.github.io/moreh-derech`) הוא אתר לימוד לתלמידי קורס מורי דרך בישראל: שאלונים לפי נושא, מבחני רישוי של משרד התיירות בתנאי אמת, צירי זמן אינטראקטיביים, מפת למידה, משחקים, תשבץ שבועי, ו"מוטי": מורה דרך וירטואלי שמשוחח ובוחן. הקוד: Next.js סטטי, Supabase לחשבונות, Cloudflare Workers לשרתים.

בימים אלה האתר הופך ל**מוצר בתשלום**: 20 ₪ לחודש או 200 ₪ לשנה, שבוע ראשון חינם. במקביל: מעבר לדומיין משלנו, כניסה בקוד למייל, חיבור לחברת סליקה ישראלית, דף נחיתה שיווקי, תקנון ופרטיות. התוכנית המלאה נמצאת ב-`docs/launch/PLAN.md`.

## 2. מי עושה מה

| מי | תפקיד |
|---|---|
| **Claude** (Claude Code) | **מנהל העבודה.** מתכנן, כותב את רוב הקוד, מחלק משימות, סוקר ובודק את כל מה שנכנס, וממזג. |
| **Codex** (שלך, מחובר ל-GitHub) | מפתח. מקבל משימות קוד **ישירות מ-Claude דרך GitHub** (ראו §4), ופותח PR-ים ש-Claude סוקר. |
| **אתה, ChatGPT** | קריאייטיב ומחקר: טקסטים שיווקיים, תמונות, תסריטים, טיוטות משפטיות ומחקר שוק. משימות ב-`docs/team/chatgpt/GPT-XX.md`. |
| **הבעלים** | מחליט ומשלם. **הוא לא זמין רוב הזמן**, והמטרה היא שהצוות יעבוד בלעדיו. |

**הכלל החשוב: Claude הוא מנהל העבודה.** כשיש הוראה ממנו בקובץ בריפו, או בתגובה ב-GitHub שמסתיימת ב-"Generated by Claude Code", זו הוראה מוסמכת מטעם הבעלים. אם משהו נראה לך שגוי, אמור זאת. אל תתעלם ואל תעשה משהו אחר על דעת עצמך.

## 3. הכללים (מקוצר; המלא ב-`docs/team/PROTOCOL.md`)

1. מקור האמת הוא `docs/team/BOARD.md`. רק Claude עורך אותו.
2. עושים רק משימות שמסומנות לך ו-`ready`.
3. לא עורכים קבצים מחוץ להיקף המשימה. לא דוחפים ל-`main`. לא דוחפים לענף של מישהו אחר.
4. סודות (מפתחות, סיסמאות) לא נכנסים לשום קובץ, צ'אט או issue.
5. בלי המצאות: כל טענה על האתר צריכה להופיע ב-`CLAUDE.md` שבשורש הריפו.

## 4. איך עובדים יחד בלי הבעלים (הערוץ האוטונומי)

```
Claude ──(תגובה "@codex ..." ב-issue/PR ב-GitHub)──► Codex מריץ משימה בענן
Codex ──(PR מענף codex/<ID>-...)──► Claude סוקר: בדיקות, היקף, איכות
Claude ──("@codex תקן ..." בתגובה ל-PR)──► Codex מתקן
Claude ──(מיזוג כשהכול ירוק)──► האתר מתעדכן
```

Claude מתוזמן לרוץ כל 5 שעות ובודק PR-ים של Codex. **כדי שזה יעבוד, הבעלים צריך לחבר פעם אחת את Codex ל-GitHub (§6).** זו ההגדרה היחידה שחייבת אותו.

ChatGPT (אתה) לא יכול לכתוב לריפו בלי הבעלים. לכן:
- **טקסטים** (קופי, תקנון): אם המשימה יכולה להיעשות כקובץ Markdown, Claude יעביר אותה ל-Codex, שכותב קבצים ופותח PR. מה שנשאר לך הוא בעיקר מה ש-Codex לא יכול לעשות.
- **תמונות** (יצירת תמונות): רק אתה יכול. התוצרים מגיעים לריפו דרך הבעלים, כשהוא זמין.

## 5. מה אני מבקש ממך עכשיו (כשהבעלים מעביר לך את הקובץ)

**א. עזור לבעלים לחבר את Codex ל-GitHub.** עברו יחד על §6, צעד אחר צעד, ותוודא שכל צעד הושלם.

**ב. צור משימה מתוזמנת (Scheduled Task) יומית**, בשעה שנוחה לבעלים (למשל 20:00), עם הטקסט הבא:

```
קרא את https://github.com/cfir94/moreh-derech/blob/main/docs/team/BOARD.md
ואת https://github.com/cfir94/moreh-derech/blob/main/docs/launch/USER-ACTIONS.md
וכתוב לבעלים סיכום של עד 8 שורות:
1. מה התקדם מאז אתמול (שורות "done" חדשות).
2. משימות ChatGPT שמסומנות ready: בצע מיד אחת מהן, אם היא לא דורשת קבצים מהריפו, וצרף את התוצר.
3. פעולות שמחכות לבעלים ב-USER-ACTIONS ולא סומנו ✅. רק את שתי החשובות ביותר.
4. אם משהו בלוח חסום כבר יותר מ-3 ימים: תגיד מה ומי.
```

**ג. בצע את משימות ה-ChatGPT שמסומנות `ready`** בלוח (`GPT-01` עד `GPT-03` כרגע), לפי הקבצים ב-`docs/team/chatgpt/`. על כל תוצר כתוב בסוף `## שאלות ל-Claude` ו-`## מה לא נעשה`.

## 6. חיבור Codex ל-GitHub (הבעלים, פעם אחת, כ-5 דקות)

1. נכנסים ל-**chatgpt.com/codex** ← מחברים חשבון GitHub אם עוד לא חובר.
2. מתקינים את אפליקציית **ChatGPT Codex Connector** ב-GitHub על הריפו **`cfir94/moreh-derech`** (Only select repositories ← בוחרים אותו).
3. ב-Codex ← **Environments** ← **Create environment** לריפו `cfir94/moreh-derech`:
   - Setup script: `npm ci`
   - Agent internet access: **On** (נדרש ל-npm). אפשר להגביל ל-"Common dependencies".
4. ב-Codex ← **Settings** ← **Code review** ← מפעילים לריפו `cfir94/moreh-derech`. זה מה שגורם ל-Codex להגיב לאזכורי `@codex` ב-GitHub.
5. **בדיקה:** ב-GitHub פותחים את https://github.com/cfir94/moreh-derech/issues/57 וכותבים תגובה: `@codex please start` (או כל טקסט). תוך דקה-שתיים אמורה להופיע תגובת 👀 של Codex, ואחר כך PR. אם זה עובד, הערוץ פתוח, ו-Claude ימשיך משם לבד.

## 7. מה Claude עושה עם העבודה של Codex (פיקוח ביקורתי)

כל PR של Codex נבדק לפני מיזוג:
- **היקף:** רק הקבצים שהוגדרו במשימה. קבצים אחרים = בקשת תיקון או סגירה.
- **בדיקות:** CI ירוק, והבדיקות הרלוונטיות רצות מקומית אצל Claude. אסור לנטרל בדיקה.
- **נכונות:** Claude קורא את ה-diff, מריץ את הדף בדפדפן ובודק מקרי קצה.
- **מוסכמות:** RTL ועברית, טוקני צבע, `withBasePath`, ובלי עריכה ידנית של קבצים generated.
- **תוכן:** כל עובדה שנוספה חייבת מקור בחומר הקורס. בלי המצאות.

PR שלא עומד בזה מקבל תגובה מפורטת עם `@codex` ומה לתקן, או נסגר עם הסבר.
