## המטרה

להפוך את האתר, שהוא היום כלי פנימי של הכיתה, למוצר שמשתמשים חדשים נרשמים אליו לבד, מקבלים שבוע ראשון חינם ומשלמים אחריו. הכסף מגיע לחשבון הבנק בלי עבודה ידנית. המוצר רץ באופן יציב על תשתית שמחזיקה אלפי משתמשים בעלות קבועה כמעט אפסית.

## הממצאים שקובעים את הארכיטקטורה

1. **אסור להריץ שירות בתשלום על GitHub Pages.** התיעוד של GitHub אומר במפורש שאסור להשתמש בו לאתר שמטרתו העיקרית עסקאות מסחריות או SaaS. לכן האתר עובר ל-**Cloudflare** בדומיין שלנו, בתוכנית החינמית. Cloudflare כבר משמש את מוטי.
2. **הכניסה הנוכחית אינה בטוחה למוצר בתשלום.** הסיסמה נגזרת מהמייל ומ"מלח" שמופיע בקוד הציבורי, ולכן מי שיודע מייל של מנוי יכול להיכנס לחשבון שלו. מחליפים אותה ב**קוד חד-פעמי למייל** וב**כניסה עם Google**.
3. **מוטי נופל משתי סיבות:**
   - **(א)** כל הודעת צ'אט כותבת ל-Cloudflare KV, שמוגבל בתוכנית החינמית ל-1,000 כתיבות ביום. אחרי כ-1,000 הודעות הכול נכשל עד חצות UTC.
   - **(ב)** המכסה החינמית של Gemini Flash היא כ-20 בקשות ביום לפרויקט, ו-Flash-Lite מקבל יותר.
   - (א) נפתר בקוד ובחינם. את (ב) מקטינים בקוד: מודל קל יותר קודם, הודעה ברורה כשהמכסה נגמרת, ומוטי רק למשתמשים מחוברים. פתרון מלא ל-(ב) דורש חיוב ב-Gemini, וזה יקרה כשיהיו מנויים.
4. **הריפו ציבורי.** כל התוכן של האתר (שאלונים, מבחנים) נמצא היום בגלוי ב-GitHub. אחרי המעבר ל-Cloudflare הופכים את הריפו ל**פרטי**, באישור הבעלים.
5. **האתר סטטי, ולכן החסימה בתשלום היא בצד הלקוח ("רכה").** משתמש רגיל לא יעקוף אותה, ומפתח נחוש יכול. בצד השרת חוסמים רק את מה שעולה כסף, כלומר מוטי. אם תהיה בעיית עקיפה, שלב מאוחר יותר יעביר את נתוני השאלונים מאחורי API.
6. **מגבלת קובץ.** ב-Cloudflare קובץ סטטי מוגבל ל-25MB, וקובץ המפה `israel.pmtiles` שוקל 95MB. הוא נשאר מוגש מ-GitHub Pages (כלי מפה ציבורי, לא חלק מהמכירה) או עובר ל-R2. ההחלטה נמצאת במשימה H-03.
7. **מבחינת היקף (פירוט ב-[`research/scalability.md`](research/scalability.md)):** בתוכנית החינמית, Supabase מחזיק 50 אלף משתמשים פעילים בחודש, ו-Cloudflare מגיש קבצים סטטיים בלי הגבלה. הצוואר הראשון הוא **מיילים**: Resend החינמי שולח 100 מיילים ביום. הצוואר השני הוא **Gemini**.

## הארכיטקטורה אחרי השינוי

```
moreyderech.com  ──►  Cloudflare Worker (static assets: out/ של Next)
                        │  דף נחיתה, האתר, Paywall בצד הלקוח
                        │
api.moreyderech.com ─► Cloudflare Worker "md-api" (חדש)
                        │  /billing/checkout   → יוצר דף תשלום אצל ספק הסליקה
                        │  /billing/callback   → הספק מודיע על חיוב → entitlements
                        │  /billing/cancel     → ביטול מנוי (חובה לפי חוק: ביטול באותה דרך)
                        │  cron יומי           → מיילי "הניסיון נגמר בעוד יומיים" וכו'
                        ▼
                     Supabase (קיים): auth (קוד למייל / Google), profiles,
                        entitlements (חדש, כתיבה רק ע"י השרת), billing_events
history-talk.cfir94.workers.dev (מוטי) ─► בודק JWT של Supabase + זכאות לפני שיחה
Resend ─► מיילי כניסה (SMTP של Supabase) ומיילים אוטומטיים
Cloudflare Email Routing ─► hello@moreyderech.com → ה-Gmail של הבעלים
```

## השלבים

הסימון: 🟢 בלי תלות בבעלים · 🟡 צריך פעולה של הבעלים (ראו USER-ACTIONS) · 🔴 דורש אישור לפני מיזוג.

### שלב 0 — ייצוב וניקיון (עכשיו)
- **M-01** 🟢 מוטי: בלי כתיבה ל-KV בכל הודעה (אסימון צ'אט חתום HMAC), סטטיסטיקה ללוגים, סדר מודלים לפי המכסה, והודעה ברורה כשהמכסה נגמרת.
- **M-02** 🟡 מוטי: workflow שמעלה את ה-Worker אוטומטית במיזוג (`CLOUDFLARE_API_TOKEN`). היום ההעלאה ידנית, ולכן תיקונים לא מגיעים לאוויר.
- **C-01** 🔴 הסרת הסרטונים של "שיעורים עיוניים" ו"שיעורים מקוונים" מהאתר ומהחיפוש.
- **S-01** 🟢 אבטחה: היום כל משתמש מחובר יכול להוסיף מחברות (`course_notebooks`). מגבילים את זה למנהלים.
- **Q-01..Q-n** 🟢 סקירת קוד וליטוש, מחולקת לפי אזורים: lint, טיפוסים, בדיקות, ביצועים, נגישות, קוד מת. חלק מזה עובר ל-Codex.

### שלב 1 — תשתית מסחרית
- **H-01** 🟡 קניית moreyderech.com ו-DNS ב-Cloudflare.
- **H-02** 🟢 בניית האתר בלי `basePath` (משתנה סביבה), ו-Worker סטטי ב-Cloudflare עם workflow פריסה.
- **H-03** 🟢 החלטה על קובץ המפה: GitHub Pages או R2.
- **H-04** 🟢 הפניה מהכתובת הישנה (`cfir94.github.io/moreh-derech/*`) לדומיין החדש, עם שמירת הנתיב.
- **H-05** 🔴 הפיכת הריפו לפרטי אחרי שהפריסה החדשה עובדת.

- **E-02** 🟡 hello@moreyderech.com: Email Routing ל-Gmail, ו-"Send mail as" דרך Resend.

### שלב 2 — הרשמה וכניסה
- **A-01** 🔴 כניסה בקוד חד-פעמי למייל (Supabase OTP), במסך אחד: מייל ← קוד ← שם ← בפנים.
- **A-02** 🟡 כניסה עם Google (צריך OAuth client ב-Google Cloud).
- **A-03** 🔴 סגירת הכניסה בסיסמה הנגזרת, בתיאום עם `israel-geo-game`. המשחק עובר לאותה כניסה.
- **A-04** 🟢 העברת התקדמות מקומית: המפתחות לפי `user_id` נשמרים. משתמש קיים שנכנס בקוד מקבל אותו `user_id`, כי זה אותו מייל ב-Supabase.

### שלב 3 — זכאות, Paywall ותשלום
- **B-01** 🔴 טבלאות `entitlements` ו-`billing_events` עם RLS (קריאה עצמית בלבד, כתיבה רק ע"י השרת), ו-RPC `start_trial()`.
- **B-02** 🟢 `src/lib/plans.ts`: מה חינמי ומה בתשלום, מחירים ו-`useEntitlement()`.
- **B-03** 🟢 רכיב Paywall ומסך "התוכנית שלי" באזור האישי: מצב הניסיון, חידוש וביטול.

## החלטות פתוחות (לא חוסמות — יש ברירת מחדל)

1. **מה נשאר חינמי אחרי שבוע הניסיון?** ברירת המחדל ב-`plans.ts` (ניתן לשינוי): דף הבית, תשבץ השבוע (סיבה לחזור כל שבוע), ספריית הקישורים, מפת המורשת, ושאלון דוגמה אחד. כל השאר בתשלום.
2. **חברי הכיתה הנוכחיים.** ההצעה: חשבון שנרשם לפני ההשקה מקבל גישה מלאה חינם עד מועד המבחן הקרוב ("מייסדים").
3. **המחיר הסופי** — אחרי הצילום של המתחרה.
